# 深渊回响 · 房间制 Roguelike RPG

程序化生成房间地图，走进房间触发战斗、宝箱、商店、祭坛或随机事件，用战利品强化自己，一路下潜到第 15 层击败深渊之主。

**Godot 4.7 + C# 原生版**：逻辑层是纯 C# 类（不引用任何 Godot 类型），渲染、输入、资源、存档全部走 Godot 原生能力。
导出的 Windows / Linux 包不依赖浏览器、Chromium 或 Electron。

早先的 Phaser 3 + TypeScript / Electron 版已经退场，代码与打包流水线一并移除（见 Issue #81）。
迁移过程、逐模块对照与性能实测留在 [godot/MIGRATION.md](godot/MIGRATION.md)。

## 快速开始

```bash
cd godot
dotnet build
godot --path .                       # 直接玩
```

依赖 Godot **4.7.2 .NET 版**与 **.NET SDK 8**，导出模板放
`~/.local/share/godot/export_templates/4.7.2.stable.mono/`。细节见 [godot/README.md](godot/README.md)。

## 构建与发布

| 场景 | 命令 / 触发方式 | 产物 |
| --- | --- | --- |
| 本地跑 | `dotnet build && godot --path godot` | — |
| 本地导出 | `godot --headless --path godot --export-release "Windows Desktop" build/win/AbyssEcho.exe`<br>`godot --headless --path godot --export-release "Linux" build/linux/AbyssEcho.x86_64` | 可执行文件 + `.pck` + `data_*` 三件套 |
| push 任意分支 | `.cnb.yml` 的 `Godot 逻辑自检` | 不产物，只验规则没被改坏 |
| 打 tag（如 `v1.4.0`） | `tag_push` | 自检 → 导出 → 创建 Release → 上传 `zip` / `tar.gz` |
| 手动触发 | `web_trigger` | 同上但不发布，用来验链路 |

产物是**三件套**，缺一不可：可执行文件 + `.pck` + `data_<产品名>_<平台>_<架构>/` 目录。
CI 把 Windows 打成 `AbyssEcho-windows-x86_64.zip`、Linux 打成 `AbyssEcho-linux-x86_64.tar.gz`。

构建镜像在 `.ci/godot/Dockerfile`：Godot 4.7.2 .NET + dotnet 8 + 双平台导出模板 + Noto CJK 字体，
镜像构建期会断言 `zip / unzip / tar / xvfb-run / dotnet` 都在——缺一个就红，而不是等导出跑完才发现。

流水线里有三道容易踩空的防线，别顺手删掉：

1. 导出后逐项断言 `.exe` / `.x86_64` / `data_*` 真的落地了——Godot 导出失败时不一定给非零码。
2. 打出来的压缩包要能解开（`unzip -t` / `tar tzf`）——`set -eu` 只管打包命令的退出码，管不了空包。
3. 在**导出的二进制**上再跑一遍 `--selfcheck` 与 `--uismoke`——编完不算完，它得能跑。

自检与导出都跑在 headless 下，唯一需要显示设备的是截图与性能基线（`xvfb-run` + OpenGL）。
headless 下 `GetImage()` 拿到的是空图，所以「画面是通的」只有截图能证明。

但**截图数张数不算证明**：曾经有五张 png、其中三张被同一张新手引导卡盖着，流水线绿了好几轮。
现在每张图在拍下去之前先自证（`--shot` 里写死判据），并写一份 `manifest.json`；
CI 再跑一次 `--from-shots=<dir>` 只读清单重放判据，图与清单作为 Commit 附件留档。

| 图 | 它必须证明的事 |
| --- | --- |

| `02-map.png` | 房间层建出来了、屏上没有覆盖层 |

没有任何控件类型或布局数得到它，只能专门问一次（`Widgets.Overlays`）。

## 验证

```bash
cd godot
dotnet build
godot --headless --path . --import
godot --headless --path . -- --selfcheck     # 逻辑自检
godot --headless --path . -- --uismoke       # 界面冒烟
godot --path . -- --bench                    # 性能基线：首帧 / 帧耗分位 / 节点数 / 托管堆
godot --headless --path . -- --play=7        # 无头试玩一整局：逐层血量、房型分布、最后一战
godot --headless --path . -- --probe=3       # 按玩家顺序真玩一局：走位/开箱/买药/换装，逐间核对
godot --headless --path . -- --probe=sweep=30  # 同一套走法连跑 30 局：死因、死在哪类房、回复来源
xvfb-run -a godot --path . --rendering-driver opengl3 -- --shot=screenshots  # 九张图 + 自证 + 清单
godot --headless --path . -- --from-shots=screenshots                        # 只读清单、重放判据
```

`--play` 走的是自检里那套「理性玩家」策略，所以它的数字能和 40 局基线对上；
它不进断言，只用来回答「这一局的血是在哪一层、哪一类房间里丢的」。

`--probe` 是另一套东西：它按玩家真的会按的顺序玩（用 `Move` 走位而不是瞬移、
开箱真的收下、进店真的买、每层存一次读一次），逐间房核对「我说我拿到了，我是不是真的拿到了」。
`--probe=sweep=N` 把它跑 N 局，只报汇总——**单局是现场，横扫才是结论**。
横扫表里有五样东西值得看：死了几局 / 通关几局、被哪一招打死、死在哪类房、
**回复从哪来**（战后奖励回血 vs 喝药，含地图上喝的那一份）、以及**钱最后流到哪去了**
（泉眼献金 / 卖旧装备 / 每层收尾还剩多少）。

几张表各自的**分母**都写在同一行里，因为它们错过的次数比结论多：

- 死因表先算账——`覆盖 N / 死亡 M 局`，对不上就直接标出来；
  认不出来的一局按**来源分桶**（`普攻:巨魔` / `普攻之外:倒下自爆` / `机制:中毒`），
  不再是一段日志尾巴。
- 「毒够重」与「毒会要命」分开报：前者是「这一回合的毒 ≥ 当前血量」，
  后者还要加上「这一层的毒死额度还没用完」（`Game.PoisonDyingBudget`）。
- 货架保底按**进门那一刻**判（`467 / 467 次进门时摆着`）：逛完之后货架当然是空的，
  那个数只能证明自己刚才买走了什么。
- `--mistake=N` 让探针偶尔算错（`light|bad|ugly` 三档错法），同一批种子跑两遍才量得出
  「一次误判的价钱」。

逻辑自检能驱动完整场战斗，靠的是 `godot/Scripts/Core` 与 `godot/Scripts/Systems` 不 `using Godot`。
`--bench` 不进 CI 断言——CI 机器负载不稳，性能是趋势，不是阈值。

## 背包与装备

背包 8 格，装备槽三件（武器 / 护甲 / 饰品）。背包里的每一件都会写出
**它给了什么**，装备中的那几件还会与身上那件比出差值（「攻击 +7（+4）」）——
面板上的「攻击 124」是总数，从这里看不出哪一件贡献了 16，而换装是这游戏里
唯一一个能反复撤销的决定，它必须可比较。比较用的尺子是攻击 ×3 / 防御 ×2 / 生命 ×1，
只为了让「攻击 +3」和「生命 +9」能摆在一起看，不是精算。

换装不是一瓶药：当前生命跟着**上限的增量**一起平移，上限涨 8 就涨 8 点血、降 8 就降 8 点血
（夹在 1..新上限）。所以反复「摘下 → 喝满 → 戴回」拿不到任何一点额外的血，
而 +最大生命那件东西的价值是「等你受伤之后才值钱」。

## 存档

- 元进展（碎片、解锁、成就、开局计数）：`user://abyss_echo_meta.cfg`
  碎片是**跨局**的那条进项：每局结算给（通关 50、阵亡 5、Boss 另计），
  只买「多一种选择」与「内容更早出现」，不买数值。五档解锁合计 1480 块
  （一局平均 300 上下，约五局），前两局各讲一次新手引导、第三局起不再出现
- 局内进度：`user://abyss_echo_run.cfg`，在下楼、战斗结算、买完东西、地图上喝药/丢道具、
  **换装 / 训练房三选一 / 祭坛（净化与血祭）**、保存回标题、以及**直接关窗**时写入。
  这几处以前只改了内存里的状态：选完训练直接关窗，回来那一次选择就凭空消失；
  换上一把更好的剑再关窗，回来又成了旧装备——而「喝药」「丢弃」「买完」当时都已经当场落盘了
- 离线不推进游戏时间：读档不刷新商店、不掉血也不回血；战场本身不存档
- 存档里那行 `seed` 存的是**地图种子**（`Game.MapSeed`），不是随机序列的种子：
  地图只由「种子 + 楼层」派生，读档要按它一模一样地重建第 1 层那张图。
  随机序列另外存一份 `rng_state`，读档后接着上次的位置走——
  这两件事都要成立，否则「继续」读出来的是「同一个种子、另一局」
- 局内所有「会变强」的装备都是运行时生成的（发 `_rN` 唯一 id），存档只带那些
  真正被引用的（装备槽 / 背包 / 货架）——所以掉落的、买到的、事件换到的都能穿过一次读档
- 金币的进出只有两个入口：`Game.EarnGold` / `Game.SpendGold`。战斗赏金、事件赏金、
  商店、血祭、事件门票全部走它们，所以「获得 / 花掉 / 余额」三本账永远对得上

## 玩法

| 操作 | 按键（键位表在 `godot/Scripts/UI/Keymap.cs`） |
| --- | --- |
| 移动 | `WASD` / 方向键，或直接点击相邻房间 |
| 等待（原地观察） | `空格` |
| 下楼 | `>` 或 `.`（需清空本层所有敌人房） |
| 背包与装备 | `I` |
| 帮助 | `H` |
| 关闭面板 / 暂停 | `Esc` |
| 战斗中解毒 | 点「解毒草」或按对应数字键 |
| 战斗中出招 | 数字键 `1`~`9`（对应行动条上的键帽） |
| 跳过 Boss 出场动画 | 空格（动画播放中任意时刻） |
| 查看本层机制 | 层数徽标右侧常驻机制名；`H` 帮助面板也有说明 |

地图上每个方块是一个房间，方块间的连线是可以走的路：

| 符号 | 房间 | 内容 |
| --- | --- | --- |
| 起 | 起点 | 每层的落点 |
| · | 空房间 | 什么都没有 |
| ! | 敌人房 | 回合制战斗 |
| $ | 宝箱房 | 三选一：三件东西里带走一件（和战后奖励同一块面板） |
| 商 | 商店 | 用金币买装备 |
| ? | 事件房 | 做出选择，结果随机 |
| † | 祭坛房 | 三种：解毒 / 付掉一截**生命上限**换 6 点攻击（代价按基础上限算，最少 6 点、最多 4%，见 `config.altars.sacrifice`）/ 第 6 层起还会出现**泉眼**：投入金币换永久的生命上限与攻击（`config.altars.offering`，一局最多 5 次；第一笔 60 起、**每深一层再贵 20**） |
| ⚑ | 精英房 | 一只按层数强化的怪（第 1 层 1.03 倍、第 10 层 1.3 倍），进房前可见属性 |
| ☥ | 训练房 | 回 40% 血，或本层所有攻击 +10%（两间训练房会累加），或给下一件装备刻一条随机词条（需解锁） |
| ♁ | 诅咒房 | 一件带负面词条的紫装，可拒绝（需解锁） |
| ☠ | Boss 房 | 每 5 层一个，第 15 层的深渊之主是最终目标 |

清空一层里所有敌人房、精英房与 Boss 房后，在地图任意位置按 `>` 下楼。HP 条会显示本层还剩几间战斗房，
底部提示条在岔口上还会说清「分别在哪一边」（如 `剩余战斗房 3（右 2 · 左 1）`），
按 `>` 被拒绝时也一样——不用自己数格子，也不用挨个死胡同撞一遍。

地图上每块地砖的右下角有一枚红点，写着**这条岔路底下还剩几场仗**（自己这一间不算），
没有红点的方向就是已经走干净的。一层里大约一半的房间是死胡同，走进去、发现是空的、
再原路走回来是这游戏里最普遍的几步路，而地图生成那一刻就知道哪一边有仗——
它有这个数，没有理由不说。

地砖外框描一圈暖橙的那一间，是**从你脚下到 Boss 的必经之路上、下一间躲不过的战斗房**；
提示条也会把两个数分开写：`剩余战斗房 3（下楼还差 1 场）`。
一层平均 3.2 场仗，挡在去 Boss 路上的只有 1.1 场——**其余 67% 的仗是可选的**。
以前只报总数，玩家的读法是「打完三场才能下楼」，代价是整整一层楼的血量。

每层的**战斗房**配额跟着深度走（`MapGen.BattlesWanted`）：第 1~4 层 3 场、
第 5~9 层 4 场、第 10 层起 5 场，补出来的只从空房里挑。定它的是一张死法分布——
100 局横扫里第 7、8、10、11 层一局都没死过，而赏金是按层涨的：
赏金在涨、泉眼从第 6 层开、货架跟着层数长，只有「路」没跟着长。

每层至少保证 1 间事件房与 1 间商店房；**补给房（商店 / 训练 / 祭坛）共用一个配额**——
第 1~5 层 1 间，第 6~10 层 2 间，第 11 层起 3 间（`MapGen.SupplyCap`）。精英房每层最多 1 间。
补给房共用一个配额是刻意的：三类各配各的、彼此不知道对方存在时，按权重抽到的第一个补给房会把剩下的空地全部吃光。

补给房的密度要跟着深度走，原因是「钱」这条线上跑出来的：模板价写死在 8~110、
楼层只加 1.5/层，而赏金是 12 + 4×层——玩家到第 8 层手上 1500 金币，
一层却只有一间店、货架上四件加起来不到 200。所以商店价格现在也跟着**钱包**抬
（超过「最贵模板价」2 倍后每倍 +25%，封顶 3 倍）。

### 关卡与通关

每一层都有一条自己的规则，Boss 层则换成 Boss 的专属机制。机制名常驻在 HUD 的层数徽标旁。

| 层 | 机制 | 这一层要你多想什么 |
| --- | --- | --- |
| 1 | 常规 | 教学层：熟悉移动、战斗与装备 |
| 2 | 瘴气 | 敌人打中你时有 20% 概率让你中毒 2 回合（毒伤按**你的血条**折算：每回合 10%，最多 18%）——该带解毒草了 |
| 3 | 狭窄 | 敌人防御 +4，但你暴击率 +15%：换个输出结构，别硬砍 |
| 4 | 尖刺 | 敌人攻击 +25%：把防御当正经资源用 |
| 5 | Boss · 熔岩爆裂 | 每 3 回合爆壳：爆壳的**那一回合**攻击 +40% 并灼烧你 2 回合 |
| 6 | 疫病 | 敌人免疫中毒，但你攻击 +4——毒系在这里吃瘪 |
| 7 | 躁动 | 敌人闪避率 20%：用高倍率技能，别用普攻磨 |
| 8 | 回响 | 敌人每回合回血（8% 但封顶 5%，见 `FloorMechanics.HealCapRatio`），而且中了毒就回不上来：拖不起 |
| 9 | 灼烧 | 敌人攻击无视你 30% 防御：防御不再是万能解 |
| 10 | Boss · 霜之镜像 | 每 2 回合展开冰镜，反弹你下一次攻击 20 点 |
| 11 | 怨恨 | 敌人倒下时自爆（其攻击力 60% 伤害）：收割也要小心 |
| 12 | 反射 | 你攻击时 25% 概率被反震 4 点：少用普攻 |
| 13 | 幽暗 | 敌人闪避 30%，且你的治疗效果减半 |
| 14 | 凝固 | 敌人防御 +2、攻击 +10%：出深渊前的最后一课 |
| 15 | Boss · 深渊领域 | 每 2 回合领域张手：当回合它的攻击 +30%、并驱散你的强化；领域范围内**你的**技能冷却 +1 回合（这条常驻，Boss 自己的技能不吃这一笔） |

通关判定是**击败第 15 层的深渊之主**。打完第 5、10 层的 Boss 只会弹一个里程碑横幅，
告诉你还差几层——深潜不会因为「打了个 Boss」就被误判成结束。

通关不是终点：结算面板会给「继续深潜」和「返回标题」两个出口。深潜到第 16 层起进入第 2 周目，
敌人攻击/防御/生命每周目 +15%、商店价格 +10%，并且每周目多一个全局负面效果
（暴戾：敌人暴击 +10% / 坚韧：敌人防御 +15% / 嗜血：敌人攻击 +10% / 贪婪：商店再贵 10%）。
第 20 层是**深渊之主·逆位**（属性为原版 2 倍，击败后拿到成就标记），
第 25 层是**三 Boss 连战**——依次打完熔岩领主、霜蚀女王、深渊之主，中途不回血；每一只都带它自己的机制（爆壳 / 冰镜 / 领域），
而这一层的敌人**倒下时会自爆**（攻击力 60%，和怨恨层同一条规则）——最后一战总得拖出点代价。第 26 层起楼层机制按 16~25 那一组循环，不会变成没有规则的空白层。

深潜段（16~24 层）每一层都有自己的遭遇组合，和 1~15 层一样写在
`game_data.json` 的 `encounterSlots` 里；缺任何一层都会在启动时报错。
没有组合的楼层会退化成「从全池随机抽一只」，而旧判据只淘汰「还没出场的怪」——
第 20 层的仗里能撞见第 1 层的巨鼠。运行期还有一层兜底：随机池只留「最近 8 层之内出场过的怪」。

每只 Boss 进门都会先播一段专属出场动画再开打：熔岩领主从岩浆里升起、霜蚀女王由四角冰晶拼成、
深渊之主从中央漩涡展开，名字各有火焰/结霜/脉动光晕效果。嫌挡事就按空格跳过。

机制的呈现位置是刻意铺开的：HUD 层数徽标右侧常驻机制名，进本时弹一次横幅说明，
起点房再报一次，战斗界面把机制名与效果摊在敌人卡下方，触发时横幅会亮一下。
玩家不该在挨打之后才从日志里悟出「原来这层有这个规则」。


### 战斗

完整的键位表见 `godot/Scripts/UI/Keymap.cs`——游戏里的 `H` 说明面板直接渲染这张表，不会和实现脱节。

回合制：你出手一次，敌人出手一次。你可以**攻击**、**防御**（本回合受伤减半）或施放**技能**，
行动条上的每个按钮都带一枚数字键帽，按数字比挪鼠标快。敌人卡片的数值行会预告它下一刀的伤害区间，
这一刀可能直接带走你时会染红；你当前的「防御中 / 攻击 +X%」状态写在战斗日志下方。

这一行的尾巴上还有**你自己的那一半**：`｜你还要 5 刀（每刀 5~9）`。
敌人卡以前把「它打你多少」写得很细（下一刀区间、毒、自爆、本回合合计），
却一个字都没说「你打它多少」——而玩家读这一行是为了算出「再挨两刀还是三刀」。
两半读的是同一个入口（`Battle.PlayerHitForecast`），技能按钮的提示里也带着
这一手能打多少。

这句预告走的是与真实结算同一条修正链路（`Battle.enemyForecast()`），
灼烧层的破防、冰封印记的降攻、Boss 大招倍率、敌人的强化倍率、
诅咒词条的受伤加成都会体现在里面，有改写时来源会跟在区间后面——
预告的数字就是你会挨到的数字，不会因为某一层机制生效而和实际打架。

- 伤害 = `攻击力 × 随机(0.8~1.2) − 防御力`，最低 1 点
- 10% 概率暴击，伤害 ×1.5
- 三个基础技能：
  - 🔥 **火球**：1.6 倍攻击力的高伤单体，冷却 2 回合
  - ✨ **治愈**：回复 30% 最大生命，冷却 3 回合
  - 💪 **强化**：下一次攻击威力 +40%，冷却 3 回合。倍率只在真正攻击后消耗，防御不会把它清掉
- 升级解锁的进阶技能（掷骨 → 毒液喷吐 → 暗愈 → 灵魂汲取 → 雷鸣）：
  - 🦴 **掷骨** / 🧪 **毒液喷吐** / ❄️ **冰霜新星**：单体伤害，倍率与冷却各不相同
  - 🩸 **暗愈**：回复 25% 最大生命
  - 🕯️ **灵魂汲取**：造成 0.8 倍攻击力伤害并**等量回血**，残局反杀的关键
  - ⚡ **雷鸣**：2 倍攻击力的重击，冷却 4 回合
- 新增五种技能类型，让战斗不只是「你一刀我一刀」：
  - ☠️ **毒雾**：立刻造成一次伤害，并让目标**每回合持续掉血 3 回合**。宝箱怪与巫妖都会放，
    中毒期间状态行会一直写着「中毒 N 回合」，回合结束的毒伤也写进日志。
  - 🕯️ **灵魂汲取**：伤害等量转化为自己的生命。血蛇靠它把「高攻低血」变成一种威胁。
- 新技能类型（由深层敌人与玩家解锁池共用）：
  - 🧯 **锈蚀**：把敌人防御压低 3 点，持续 3 回合。对石头傀儡、锈蚀巨像这类高甲单位有奇效
  - ❄️ **冰封印记**：让敌人攻击下降 25%，持续 3 回合
  - 🪨 **石肤**：敌人给**自己**加防御，按自身基础防御的 25% 折算，持续 2 回合。
    它加的是点数不是比例——同一刀打在防御 14 和 18 的怪身上减伤不一样多，
    所以数据里的说明只谈「涨了几点防御」，不谈「受到的伤害降低百分之几」
  - 🌀 **相位穿行**：本回合闪避率大幅提升，敌人攻击落空
  - 💥 **震颤**：造成伤害并眩晕敌人 1 回合——被震住的敌人**下一次出手**直接作废
    （按「它自己的出手机会」计，不是在你这一回合末就扣掉）
- 敌人 AI：45% 攻击 / 30% 防御 / 25% 技能（`config.enemyAi`）。「技能这一档抽到了但
  一个都没准备好」时退成普攻，不会白送一次防御
- 防御姿态只保「挨打的那一回合」。玩家先手，所以敌人的姿态要护到你的下一刀才收——
  它选的防御是真实减伤的，不是一次空摆——你按防御之后，敌人卡上的「下一刀」
  也会跟着折价（`伤害减少 50%`），而不是照旧报一个原数

#### 战斗反馈

伤害、治疗、持续伤害都会在对应角色头顶弹浮动数字：普通伤害红色、暴击橙色且字号大一半、
治疗绿色带 `+` 号、中毒灼烧浅绿小字、Boss 大招深橙大字。五种技能各有专属粒子特效
（冰霜新星放射、雷鸣闪白加折线闪电、石肤绕身三角、灵魂汲取连线回流、毒雾漂浮绿雾），
全部用矢量现画。战斗中按 `V` 可以随时关掉特效回到纯文本模式。

日志按事件类型着色：玩家行动白、敌人浅红、状态变化黄、暴击金、治疗绿、Boss 紫红；
新条目从底部滑入，Boss 大招放大加金边框、击杀绿色高亮、你濒死时挨打那行会闪。

### 成长

- 击败敌人累积**经验**（HUD 上的紫条）。升级后生命与攻击成长、每 3 级加一点防御，
  并从技能池里依次解锁新招式（掷骨 → 毒液喷吐 → 暗愈 → 灵魂汲取 → 雷鸣）。
  升级的生命是**按上限的增量涨**的，不会顺带当一瓶大药——想回满得靠药水和事件。
  这条「血跟上限走」的规矩只有一处实现（`Game.BeforeMaxHpGrows`）：`Leveling` 只改数值，
  血由它补。两处都补的时候，带「脆弱躯壳」的玩家升一级就会把血顶到上限之外。
- 战斗胜利后**三选一**奖励：装备道具 / 金币 / 回血
- 商店的货架分开摆：一件本层档位的装备 + 一瓶回血药 + 一件战术道具 + 0~1 格随机；价格随楼层与你的钱包浮动
- 背包 8 格，满了可以卖掉一件（三成价）或丢掉；装备武器/防具/饰品直接加属性
- 背包里的**炸弹**可以在战斗中投掷，造成 25 点伤害，**无视防御力与防御姿态**——写多少就是多少
- **解毒草**同样能在战斗中使用：立刻解除自身中毒，占用一个回合。中毒每回合都在掉血，
  硬扛三轮往往比浪费一个回合更亏
- **毒按血条折算，不按层数膨胀**：每回合掉你最大生命的 10%，最多 18%（封在 20 点）。
  60 血的号是 6 点、137 血是 12 点、200 血是 20 点——血越厚毒越重，但它永远只是一截，
  不会像以前那样在深层变成「一回合掉掉四分之一条命」。毒是环境的账：
  瘴气与灼烧都问同一个算式（`EntityRules.PoisonPowerFor`），不看「这一刀打出了多少」。
- **毒会杀人，但不会一直杀**：一层里中毒最多毒死玩家 `1 + (层数-1)/5` 次（第 1~5 层 1 次、
  第 6~10 层 2 次、第 11~15 层 3 次，封顶 4）。额度用完之后毒继续疼，但只扣到剩 1 点——
  日志会明说「撑住了，毒素没能带走你」。这条额度跟存档一起落盘，读档不会白拿一次。
- 回响层敌人的每回合回血**封顶 5% 最大生命**，而且中毒的敌人回不上来：靠「回得比掉得快」
  拖赢一场战斗是不可能的
- 战斗中可以**逃跑**（Boss 战除外），损失 5 点生命；房间不会因此被清空，随时可以回来再打。逃跑会一并结束这场战斗的临时状态——中毒、降攻、破防、眩晕都不会跟着你回地图。残血时逃跑会真的死在路上，它不是免死金牌

升级曲线与收益都在 `game_data.json` 的 `leveling` 段：`baseXp` / `growth` 决定节奏，
`hpPerLevel` / `attackPerLevel` / `defenseEveryLevels` 决定收益，`pool` 是技能解锁顺序。

### 难度

- 普通敌人随楼层变强（每层成长率 `config.enemyGrowth`，当前 5%），且**弱怪不会一路跟到深层**（每只怪都带 `minFloor`，到点才进场）
- Boss 阶梯（第 5 / 10 / 15 层）数值远超普通敌人，**必须靠装备、升级和技能**才打得过——空手去打必输
- 升级让「打得越深 → 越强」接上了同一条线，但深层的敌人还是涨得更快：
  想要打到第 15 层，仍然得把装备、升级和经验分配都算清楚
- 深层的威胁不只是数值：宝箱怪与巫妖会下毒，血蛇会汲血，石头傀儡硬得离谱
- 遭遇组合（`encounterSlots`）里的每只怪都必须在那一层之前就能出场，写错了启动直接报错——
  以前它会静默整组跳过，玩家看到的是「这一层怎么只有两种敌人」

## 数据驱动

所有内容都在 `godot/Data/game_data.json` 里：技能、道具、怪物、Boss 阶梯、事件、房间权重与全局数值。
加一件装备、一个事件或一档 Boss 通常只改这个文件，不用碰代码——`bossStages` 决定第几层刷哪只 Boss，
`config.finalFloor` 决定通关层，怪物身上的 `minFloor` 决定它从第几层开始出现。

楼层机制同样是数据：`floorMechanics` 定义每种机制的名字与说明，`floorMechanicMap` 把楼层号映射到机制 id，
`bossMechanics` 定义三只 Boss 的专属规则（触发周期、攻击倍率、反弹伤害、冷却惩罚）。
机制 id 与实现（加属性、挂中毒、闪避、自爆、治疗减半）在 `godot/Scripts/Systems/FloorMechanics.cs` 里一一对应，
改数值或加一层只动 JSON；启动时会校验每一层都有机制、且机制 id 都存在。

数据在启动时会校验：怪物引用了不存在的技能、事件选项没有结果、背包容量非法等都会**立刻报错**，而不是玩到一半才崩。

## 已知取舍

- 自动化机器人会看技能栏了（倍率 ≥1.3 的伤害技能会放），但仍然只是下限：
  它不会为词条做取舍，换装只按攻/防/生命的加权值算。
- 技能按钮上写的是「还要等几回合」：冷却 2 的火球放完显示「还要 2 回合」，
  也就是再打两个回合就能放——那个数就是冷却本身，不是「冷却 + 1」。
- 每层都有机制与 Boss 专属规则，但机制都是「单层一条」：同一层内不会出现两种机制叠加，
  也没有跨层持续的场地效果（腐蚀地形、永久光环之类）。
- 通关层是第 15 层，之后不会自动继续——想刷更深可以自己改 `config.finalFloor`
  并在 `bossStages` 里补一档 Boss，无限下潜仍需要更细的数值曲线。
- 只出 Windows / Linux。macOS 需要另一套导出模板与 Apple Developer 证书签名。

## 界面层序

画面上谁能压住谁，只写在一个地方：`godot/Scripts/UI/Layers.cs` 的 `StageOrder`。

| 层 | 谁在这一层 |
| --- | --- |
| `Backdrop` | 纯色场、氛围层、战斗舞台（墙 / 透视地砖 / 擂台） |
| `Panel` | 敌人卡、行动条，以及地图上下两条 HUD 条带的底 |
| `Stage` | 舞台上的人物，与承载它们的空容器 |
| `Float` | 伤害数字 |
| `Fx` | 技能粒子与命中特效 |
| `EnemyChip` | 组合战里那排小卡 |
| `Actor` | 地图上「你在这儿」那一块 |
| `Legend` | 地图上那块图例（横带或竖带，看窗口宽度） |
| `Toast` | 浮动提示（「那边没有路」） |
| `Overlay` | Boss 出场演出、房间交互面板（连带压暗层） |

规矩只有一条：**要压住谁，先说出「我是哪一层」，不要写字面量。**
Godot 里同级节点 `ZIndex` 相同就按「谁先 `AddChild`」叠——而添加顺序会在重构里悄悄变，
错了不抛异常、不改任何尺寸，只在截图上看得出来。上一轮敌人卡上半截是墙色就是这么来的：
舞台的墙与两块条带都是 0，谁先加谁在下。

界面冒烟里钉了四条：层号不许两两撞车、几条明写的上下关系（面板压背景、人物压面板、
飘字压人物、粒子压飘字、图例压玩家、提示压图例、弹窗压提示）、地图与战斗场景里实测的 z 值，
以及**源码里不许再出现裸的 `ZIndex = 数字`**（这条读源码，导出产物里没有 `.cs`，会跳过）。

## 光怎么画

**大面积、低对比的底，一律走软衰减，不许「一摞同心椭圆」。**

`Paint.Glow` 画的是 `layers` 个同心椭圆，一层比一层淡。在深色底上，
「一层比一层淡」的每一层都留着一条 1/255 的边——层数够多时人看不出来，
放大两倍就是一圈圈的环。Boss 出场那屏曾经是 `Glow(9 层)` 再叠三圈填实椭圆，
一整屏 12 条同心边界，读起来是「一张蜘蛛网」而不是「一个深渊」。

要软，就用 `Paint.SoftEllipse` / `SoftDot`：`GradientTexture2D` 的径向填充，
一次画完，外边界是 0 透明度。它不是贴图资源——在函数里按半径现建、画完就丢，
包里依然什么都没有。

这条规则有两个推论，都是被截图逼出来的：

- **加层数治不了环。** 「每环不超过 3px」那一版实测中心仍是三四道台阶：
  每环都要覆盖一次，低亮度区里 1/255 就是一道边。**磨细台阶不是消掉台阶。**
- **氛围不是加装饰，是加「光从哪来」。** 舞台两侧压一道软衰减之后，
  同一套坐标下它就成了一张「中间一盏顶灯」的舞台。它不动任何几何，
  所以不会碰布局的账。

界面冒烟里有一条读源码的判据：`Arena.cs` / `UiFrame.cs` / `Paint.cs` 里
不许再出现 `Paint.Glow(`（注释先剥掉）。小面积、高对比的地方用 `Glow` 没问题，
但这三个文件画的都是大面积底。

## 画出来才算

**控件存在不等于它被画出来。**

被更大的 z 盖住、被半透明黑幕罩住、被父级裁掉——这三种在控件树里长得一模一样：
名字在、`rect` 在、`ZIndex` 也在。第 41 轮「战斗界面下半截没画出来」时，
自检 125 绿、冒烟 64 绿、七张截图自证全过，因为**没有一条判据问过「这一屏上
到底有没有那些像素」**。

所以 `--from-shots` 除了重放每张图的自证，还会在图上数像素：行动条那排按钮的框
比卡面亮、玩家血条是绿的、地图 HUD 的血条是红的、经验条是蓝的。
阈值很松，它抓的是「整块没画」，不是配色跑偏。

这一条上线第一次就抓到了东西——抓到的是**判据自己写错**（我把玩家血条写成了「红」，
而玩家的是绿的）。这也正是它值得有的理由。
